## Обещание

**Кому:** роли R402 Дизайнер (FX5, работает inline внутри Claude Code / VS Code).

**Зачем:** сейчас разбор макета Figma идёт только через то, что пользователь опишет словами или пришлёт скриншотом — теряются точные значения (spacing, цвета, имена компонентов, auto-layout), нет способа сослаться на слой напрямую. Это узкое место для всех трёх сценариев ниже.

**Что получит потребитель:**
- Чтение структуры выбранного узла/файла Figma (слои, компоненты, свойства) прямо в сессии, без ручного экспорта.
- Возможность сослаться на конкретный макет по ссылке/selection и получить точные значения дизайн-токенов, а не пересказ.
- Основу для генерации UI-кода по макету — точные размеры/отступы/имена компонентов, не приблизительные.

**Триггер:** пользователь (в роли R402 или обращаясь к ней) даёт ссылку на макет Figma или просит поработать с уже открытым в Figma выделением.

**Время отклика:** синхронно в рамках одного обращения к MCP-инструменту (без фоновых задач).

**Режим отказа:**
- Figma MCP недоступен (сервер не запущен / не авторизован) → явное сообщение о недоступности, не молчаливый пересказ по памяти или выдумывание структуры макета.
- У пользователя нет доступа к запрошенному файлу Figma → явный отказ с причиной (нет прав), не тихая пустая структура.

## Инвариант

- [ ] R402 не выдумывает содержимое макета, если Figma MCP недоступен — явно сообщает об ограничении, не подменяет реальные данные догадкой.
- [ ] Подключение Figma MCP не создаёт конфликтов с платформенными MCP (`knowledge-mcp`, `digital-twin-mcp`) — по namespace-конвенции DP.SC.023 (`ext-*` для вендорских).
- [ ] Учётные данные/токен доступа к Figma не коммитятся в git — хранятся вне репозитория (по аналогии с остальными секретами вендорских MCP).

## Сценарии использования

### Сценарий 1: Спецификация экрана (потребитель — WP-16, экран настроек уведомлений)

**Кто:** R402 Дизайнер (по запросу пилота).
**Когда:** перед реализацией нового экрана mobile-new (COM-06).
**Что делает:**
1. Пилот даёт ссылку на макет экрана настроек в Figma.
2. R402 читает структуру через Figma MCP: слои, компоненты, отступы, состояния.
3. Формирует спецификацию экрана (компоненты, состояния, дизайн-токены) для передачи в реализацию (WP-16).

### Сценарий 2: Ревью макета

**Кто:** R402 Дизайнер.
**Когда:** пилот подготовил новый макет и просит проверить консистентность с UI-kit.
**Что делает:**
1. Читает структуру макета через Figma MCP.
2. Сверяет использованные компоненты/стили с существующим UI-kit/дизайн-токенами.
3. Отмечает расхождения (не переиспользованные компоненты, самодельные стили вместо токенов) — инвариант роли R402 «переиспользовать компоненты, не плодить стили».

### Сценарий 3: Генерация UI-кода из макета

**Кто:** R402 Дизайнер (в связке с реализующей ролью, например R6 Кодировщик).
**Когда:** макет готов и утверждён, нужен код компонента/экрана.
**Что делает:**
1. Читает точную структуру макета (размеры, spacing, auto-layout, имена) через Figma MCP.
2. Генерирует код компонента на основе точных значений — не приблизительно по описанию.

**Тест приёмки:** дать R402 ссылку на тестовый макет в Figma → в ответе сессии видна реальная структура макета (имена слоёв/компонентов из самого файла), не пересказ пользователя.

## Не гарантирует

- Двустороннюю синхронизацию (запись изменений из Claude обратно в Figma) — обещание касается только чтения.
- Работу без доступа пользователя к макету (нет открытого файла/токена → нет доступа, см. режим отказа).
- Автоматическую публикацию сгенерированного кода — генерация кода из сценария 3 попадает в обычный review-цикл, не деплоится напрямую.

## Антипаттерны

- ❌ **Выдумывание структуры макета** при недоступности MCP — молчаливая замена реальных данных догадкой недопустима (см. инвариант).
- ❌ **Самодельные стили вместо переиспользования UI-kit** — тот же антипаттерн, что и в общей роли R402, здесь особенно легко возникает при генерации кода из макета без сверки с существующими компонентами.
