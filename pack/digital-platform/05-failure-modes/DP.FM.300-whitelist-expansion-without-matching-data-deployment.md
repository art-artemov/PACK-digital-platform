# DP.FM.300 — Whitelist расширен, данные под новые значения ещё не развёрнуты

## Паттерн

Merge веток одним коммитом приносит и код, расширяющий whitelist допустимых значений (напр. список поддерживаемых языков), и — отдельно, не обязательно тем же коммитом — данные под новые значения (инфоблоки, файлы строк). Между «код принимает новое значение» и «данные для него существуют» образуется окно, в котором API начинает штатно обрабатывать запросы к несуществующим сущностям вместо отказа, потому что whitelist-проверка формально пройдена.

## Почему возникает

Whitelist в коде — это проверка «значение вообще допустимо», а не проверка «данные под это значение развёрнуты». Код и данные — разные единицы деплоя (git push кода vs применённая миграция/наполнение инфоблоков), но воспринимаются как одна операция «слияние ветки».

## Симптом

После слияния API принимает параметр (напр. `language=es`) без ошибки, но ниже по потоку — пустая выдача или тихий сбой, потому что соответствующих данных нет.

## Условие, при котором окна не возникает

Если данные (миграция, наполнение) применены раньше или одновременно с кодом — окна нет. Но это нужно проверять отдельно от факта самого слияния (см. [AS.M.086] — метод проверки такой предпосылки перед необратимым действием).

## Правило

Код, расширяющий whitelist, и данные под новые значения whitelist — одна единица деплоя, не две независимые. Порядок разворачивания (данные → код или синхронно) фиксируется явно, не оставляется на волю очерёдности merge.

## Применимость

Любой whitelist/enum допустимых значений, где значение подразумевает существование связанных данных: языки, фиче-флаги с обязательным конфигом, типы сущностей с обязательными связанными таблицами.
