# DP.FM.281 — Секреты в git-истории: ротация обязательна, HEAD-удаление недостаточно

## Паттерн

Найден закоммиченный секрет в конфиг-файле (не .env, а PHP/JSON/YAML конфиг) → команда удаляет файл из HEAD → считает задачу закрытой. Секрет продолжает жить в git-истории, доступен через `git log --all`.

**Когнитивная ловушка:** «Я удалил файл → секрет убран» — неверно. Git хранит всю историю объектов.

## Отличие от DP.FM.026

| Аспект | DP.FM.026 | DP.FM.281 |
|--------|-----------|-----------|
| Тип файла | `.env` (dotfiles) | Любой конфиг (PHP, JSON, YAML) |
| Фокус | Процедура ликвидации | Когнитивная ловушка HEAD-удаления |
| Паттерн замены | `.env.example` | Per-host файл с graceful degradation |

## Двухслойный характер

1. **Слой 1:** Секреты попали в git (misconfiguration, добавлены явно в конфиг)
2. **Слой 2 (часто пропускается):** Удаление из HEAD не убирает секрет из истории → ротация обязательна

## Fix

**Порядок действий (оба, не один):**
1. **Немедленно ротировать** скомпрометированный токен — как если бы он уже использован злоумышленником
2. Вынести секрет из репозитория в файл вне git

**Опционально (при публичном репо или утечке клонов):**
3. Переписать историю (`git filter-branch` / BFG Repo Cleaner) + force push

## Целевой паттерн размещения секретов (legacy-проект)

Per-host файл вне репозитория рядом с точкой использования (например, `.settings_extra.php`). Код читает с graceful-деградацией: нет секрета → функция молча выключена. Локальная разработка не требует секрета.

## Правило

**Секрет в git-истории = скомпрометированный секрет**, даже если удалён из HEAD.
Порядок: обнаружение → ротация → вынос → опционально rewrite истории.
