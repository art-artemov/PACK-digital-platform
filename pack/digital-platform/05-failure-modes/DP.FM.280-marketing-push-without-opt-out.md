# DP.FM.280 — Маркетинговые push-уведомления без механизма opt-out

## Паттерн

Push-уведомления маркетингового типа реализованы без возможности отписки (opt-out) — тип захардкожен как «обязательный» или API возвращает ошибку при попытке отписаться.

## Почему это ошибка

Правила сторов (Google Play, App Store) и нормы consent-менеджмента: транзакционные уведомления могут быть обязательными, маркетинговые — только opt-out. Нарушение = риск отзыва приложения из стора.

## Симптом

- API возвращает `422 "нельзя отменить"` для маркетинговых типов
- В таблице подписок тип помечен флагом `required: true` без обоснования транзакционной природы

## Механизм возникновения

```
Исходный дизайн: «действия пользователя → не отключаемы» (разумно для транзакционных)
                  ↓
Все типы → один API path → одна заглушка "нельзя отменить"
                  ↓
Маркетинговые типы унаследовали ограничение транзакционных
```

## Fix

Флаг `required` в справочнике типов (не hardcode в коде): транзакционные = `required: true`, маркетинговые = `required: false`. API проверяет флаг, не тип. Добавление нового типа = правка данных, не кода.

## Правило

**Маркетинговые push без opt-out = нарушение требований сторов.**

Тест: «Тип "обязательный"? Обязать — значит транзакционный по природе (OTP, подтверждение заказа). Если нет — `required: false`».

## Применимость

Любая система push-уведомлений с несколькими типами. Переносимо на email-маркетинг (CAN-SPAM, GDPR).
