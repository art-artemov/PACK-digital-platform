# DP.FM.287 — 3-way merge шаблона затирает пользовательские секции (L2/L3)

## Паттерн

При `update.sh` (3-way merge: base=старый шаблон, ours=пользователь, theirs=новый шаблон) merge-алгоритм **не различает** платформенные (L1) и пользовательские (L2/L3) секции внутри одного файла.

Если новый шаблон радикально изменил раздел (например, сжал §8 из 90 строк в одну ссылку), merge применяет это изменение и к пользовательской зоне — **тихо заменяет авторский контент на платформенный**.

## Симптом

- После `update.sh` пользовательские секции (§8 Staging, §9 Авторское в CLAUDE.md) значительно укоротились
- `git diff` после merge показывает потерю пользовательских строк
- При отсутствии git-репо в корне IWE — потеря обнаруживается только постфактум по пустым разделам

## Инцидент

`update.sh` заменил 90-строчный авторский §8/§9 на короткую фразу `→ скилл author-mode` из нового шаблона — тихая потеря всего staging-контента. Обнаружено через `git diff` в корневом репо IWE (созданном этой же сессией как backstop).

## Причина

Инвариант «§7: L2/L3 не платформенные» существует только как текстовое соглашение. Merge-алгоритм его не читает и не применяет.

## Отличие от DP.FM.335

DP.FM.335 — install-скрипт целиком перезаписывает конфиг-файл (`cp default → target`), фикс — seed-if-absent. Этот FM — **частичный** 3-way merge внутри одного файла не различает построчно зоны L1/L2/L3, фикс — маркер границы зон. Разная гранулярность дефекта: whole-file replace vs merge-algorithm blind spot внутри файла.

## Fix-паттерны

1. **Маркер `<!-- PLATFORM-END -->`** в CLAUDE.md: всё после него — copy-through `ours` без попытки merge
2. **Детект конфликтов в пользовательской зоне** с отдельным предупреждением (не тихий merge)
3. **Backstop-репо** в корне IWE: любая перезапись видна через `git diff` до коммита (немедленный workaround)

## Правило

**После каждого `update.sh` — проверять `git diff` на потерю пользовательских секций (L2/L3) до коммита.**

Коммит сразу после `update.sh` без проверки diff = риск тихой потери кастомного контента.

## Применимость

Любой шаблонный инструмент с 3-way merge (update.sh, cookiecutter updates, ansible template pulls),
где один файл содержит платформенные и пользовательские зоны без машиночитаемых маркеров границы.
