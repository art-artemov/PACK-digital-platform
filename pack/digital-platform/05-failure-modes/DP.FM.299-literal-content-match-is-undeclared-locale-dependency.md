# DP.FM.299 — Литеральный поиск по контенту как необъявленная зависимость от локали

## Паттерн

Шаблон применяет оформление (подсветку, ссылку, иконку, ветвление), **отыскивая литеральную фразу** в тексте, приходящем из базы. При смене языка текст приходит на другом языке, подстрока не находится, оформление молча исчезает — страница при этом выглядит целой.

**Случай WP-93:** шаблон подсвечивал термин «Портальные Ворота», ища эту фразу в тексте. В английской версии термин в базе звучит как «A Portal Gate» — восемь подзаголовков содержат термин, ни один не подсвечен.

## Почему типовая вычитка перевода это не ловит

Вычитка ищет **появившийся** русский текст на нерусской странице. Здесь искать надо **пропавшее оформление** — глазами это не воспринимается как ошибка: текст на месте, язык правильный, просто нет выделения.

## Приёмочное следствие

**При проверке локализации сравнивать версии по наличию оформления (выделения, ссылки, иконки), а не только по языку букв.** Практически: открыть обе версии страницы рядом и сверить, что оформленных элементов столько же.

## Лечение

| Вариант | Что делать | Когда предпочтителен |
|---------|-----------|---------------------|
| Вынести искомую фразу в файл перевода | Русский ищет «Портальные Ворота», английский — «Portal Gate» | Быстрый фикс, шаблон менять не нужно |
| Перенести разметку в сам контент | Оформление приходит из базы, шаблон ничего не ищет | Структурно правильнее — снимает зависимость целиком |

## Применимость

Любая логика, привязанная к литеральному значению контента: `str_replace`, поиск подстроки, ветвление по тексту, регулярное выражение по человекочитаемой фразе. Класс шире подсветки — так же ломаются условия показа блоков и правила маршрутизации, написанные по тексту.
