# DP.M.394 — Авто-пауза delivery-очереди по двойному порогу ошибок

## Определение

Fail-safe для массовой outbound-доставки: автоматическая пауза при достижении одного из двух независимых порогов ошибок с дедуплицированным алертом.

## Проблема

При системном сбое (внешний сервис недоступен, Redis упал) массовая рассылка молча продолжается, расходуя ресурсы и искусственно ухудшая метрики кампании.

## IPO

| Элемент | Описание |
|---------|----------|
| Входы | Поток результатов доставки (success/fail) по кампании |
| Обработка | Два независимых триггера: относительный (rate при достаточной выборке) и абсолютный (N подряд) |
| Выходы | Пауза кампании + одиночный алерт (дедуп по campaignId) |

## Шаги метода

1. **Относительный триггер:** если `processed ≥ MIN_SAMPLE` (напр. 500) И `failed_rate > THRESHOLD` (напр. 20%) → пауза.
2. **Абсолютный триггер:** если `consecutive_failures ≥ CONSECUTIVE_LIMIT` (напр. 50) → пауза (независимо от истории).
3. При срабатывании любого триггера: остановить обработку батчей + отправить алерт в мониторинг.
4. Дедуп алертов по campaignId: одна кампания → максимум одно событие (предотвращает флуд).
5. Параметры (`MIN_SAMPLE`, `THRESHOLD`, `CONSECUTIVE_LIMIT`) — конфигурируемые, не хардкод.

## Связь с классификацией ошибок

Работает поверх [DP.D.247](../01-domain-contract/01B-distinctions.md) (FCM dead/retry/quota) — считает именно `retry`-класс ошибок как кандидатов в failed_rate; `dead`-токены не должны засорять метрику (это ожидаемый исход, не сбой).

## Применимость

Переносимый паттерн самозащиты для любого воркера с outbound-доставкой: email-рассылки, SMS, webhook-доставка. Два независимых триггера — ключевое инженерное решение (не только конкретные пороги). Не привязан к FCM или Sentry.
