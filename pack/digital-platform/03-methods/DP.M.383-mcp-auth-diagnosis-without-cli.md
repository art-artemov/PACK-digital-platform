# DP.M.383 — Диагностика авторизации HTTP MCP-сервера без работающего CLI

## 1. Определение

Метод проверки статуса авторизации HTTP MCP-сервера когда штатная команда `claude mcp list` недоступна — CLI сломан, не установлен или выполняется в headless-режиме.

## 2. Проблема

Когда `claude mcp list` недоступен, нет прямого способа узнать состояние MCP-сервера: жив ли, настроен ли, авторизован ли. Без диагностики неочевидно, чинить ли CLI или настраивать OAuth заново.

## 3. IPO-паттерн

| Элемент | Описание |
|---------|----------|
| Входы | Конфигурационный файл `.mcp.json` или `~/.claude.json`; URL сервера |
| Обработка | Цепочка проверок: конфиг → HTTP liveness → OAuth-токен |
| Выходы | Диагноз: «не настроен» / «жив, не авторизован» / «авторизован» |

## 4. Шаги метода

1. **Читать конфигурацию.** Найти запись сервера в `.mcp.json` (`mcpServers.<name>`) или в `~/.claude.json`. Определить тип (HTTP/stdio) и URL.

2. **Liveness check.** HTTP-запрос к endpoint (любой путь):
   - `401` → сервер жив, требует авторизации
   - `200` → сервер жив и авторизован
   - timeout / connection refused → сервер недоступен

3. **Token check.** При `401`: проверить наличие OAuth-токена в `~/.claude.json` (`mcpServers.<name>.token` или аналог).

4. **Вывод:**
   - Нет конфигурации → сервер не настроен в клиенте
   - `401` + нет токена → жив, нужна OAuth-авторизация (интерактивная сессия `claude` → approve)
   - `401` + есть токен → токен устарел или отозван; перепройти OAuth
   - `200` → авторизован; проблема на стороне CLI, не сервера
