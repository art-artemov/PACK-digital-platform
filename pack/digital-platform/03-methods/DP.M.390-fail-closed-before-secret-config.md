# DP.M.390 — Fail-closed до конфигурации секрета: 401 до появления auth-конфига

## Определение

Паттерн деплоя защищённого server-to-server эндпоинта: код выкатывается раньше секрета, и **до появления конфигурации эндпоинт обязан отказывать (401)**, а не пропускать запросы.

Отсутствие секрета = «auth включён и никого не пускает», **не** «auth выключен».

## IPO

- **Вход:** новый эндпоинт с bearer-auth; секрет ещё не внесён в конфиг хоста
- **Процесс:** код проверяет `isset($config['secret'])` → если нет → 401 (не 500, не bypass)
- **Выход:** эндпоинт работоспособен структурно, но недоступен без секрета; после внесения конфига начинает принимать трафик

## Дополняющий приём

**Шаблон конфиг-блока в PHPDoc** самого метода:

```php
/**
 * Auth config required in .settings_extra.php:
 * 'push_feedback_secret' => 'your-secret-here',
 */
```

Человек, вносящий секрет, находит формат рядом с точкой использования — не в отдельной документации.

## Различение со смежными паттернами

| Ситуация | Паттерн |
|----------|---------|
| Опциональная функция без секрета | Graceful degradation (тихо выключена, не 401) |
| Входящий server-to-server канал | **Fail-closed** (401 до секрета) |
| Outbound вызов без credentials | Fail-fast (исключение при старте) |

## Место в семействе fail-closed методов Pack

Тот же принцип «отказ вместо тихого прохода при неполном состоянии», разные триггеры:
- `DP.M.298` — недоступность внешнего scope-сервиса в рантайме
- `DP.METHOD.164` — неизвестное/отсутствующее значение параметра режима
- `DP.M.390` (этот) — секрет ещё не внесён в конфиг на этапе деплоя (code-first, config-later)

## Применимость

Любой серверный эндпоинт, принимающий машинный трафик с bearer-auth. Особенно — при «code first, config later» стратегии деплоя (код выкатывается в основном релизе, секрет вносится отдельно).
