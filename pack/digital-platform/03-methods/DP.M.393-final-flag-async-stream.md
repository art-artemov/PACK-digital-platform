# DP.M.393 — Финальный флаг для завершения периодического feedback-потока

## Определение

Паттерн сигнализации завершения асинхронного потока: последняя порция данных несёт флаг `final: true`, позволяя consumer'у немедленно обновить статус без ожидания таймаута.

## Проблема

В pull-модели с периодическими порциями consumer не знает: producer «завершил» или «завис»? Без явного сигнала единственный вариант — ждать таймаута или поллить статус.

## IPO

| Элемент | Описание |
|---------|----------|
| Входы | Поток периодических порций данных с неизвестной длительностью |
| Обработка | Producer добавляет `"final": true` к последней порции |
| Выходы | Consumer обновляет финальный статус немедленно; дополнительный polling не требуется |

## Шаги метода

1. Producer отправляет данные порциями (например, каждые 30 с).
2. При завершении работы последняя порция содержит `"final": true`.
3. Consumer при получении `final: true` выполняет финализацию (обновление статуса, закрытие сессии).
4. Промежуточные порции без `final` обрабатываются как «поток продолжается».

## Применимость

Универсальный паттерн для любых асинхронных потоков с неизвестной длительностью: batch jobs, long-running imports, export streams. Не привязан к push-домену.
